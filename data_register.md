# The data register

What every file this pipeline reads is, where it is now, which computations stand on it, and what it costs to get it back. Generated by `data_register.py`; do not edit, the next run overwrites it.

## How a file is looked up here

By its bytes. Each artifact of this repository records the name, the size and the sha256 of everything its producer read, and this register resolves those hashes over a declared search area. A file that has been moved is found and its new address is printed; only a file no bytes in the area carry is called absent. Looking up by path answers **no** for a file that moved and **yes** for a stale copy at the expected address, and both of those have happened here.

## The search area

**What this describes.** This repository, the data directories the acquisition log names as the home of data on this machine, and the documents of the parent workspace that artifacts of this repository declare as inputs, each named one at a time under search_areas below.

**What this does not describe.** Everything else on the machine this ran on. The workspace around this repository is NOT walked in this mode, so no count in this file is a census of a local disk, and a file's absence from this register is not evidence that the file is absent from that disk. What is claimed here is what the declared areas hold, and nothing about what they do not cover.

The second mode, run as data_register.py --full-local-census, replaces the third area with a walk of the whole workspace. It answers a question about one machine, and nothing this repository ships is built from it.

| area | where | present | why it is searched |
|---|---|---|---|
| `tree` | `.` | yes | this repository: every artifact, every script and every derived intermediate a run leaves beside its producer |
| `data` | `../02_data` | yes | ../02_data, whose six data directories the acquisition log names as the home of data on this machine, and the acquisition log itself. It sits outside this repository because a raw day is gigabytes; a clone without it gets a register over the tree and this area marked absent |
| `workspace_documents` | `..` | yes | the documents of the parent workspace that artifacts of this repository declare as inputs, named one at a time rather than found by walking the workspace: a walk reports every file of one working copy, and the files it adds are not files this pipeline reads |

The area holds 1,027 files and 12.99 GB. This run hashed 169 of them, 6.51 GB: a file can only carry a declared identity if its size equals the size recorded beside that identity, so size is a free necessary condition and only size-matching files are hashed. Files whose name matches a declared name are hashed at any size, so that a changed file at a recorded address comes out as changed rather than as absent.

## Calibration

Two instruments print counts here and each one gets a pair, because a resolver that finds everything and a resolver that finds nothing both print a tidy table, and a sorter that files everything under an accounted-for heading prints a zero in the column that matters.

Both are derived at run time from artifact.py, the module this file imports, so neither can go stale and neither names a live defect of the tree. The first carries that file's true sha256 and a recorded address the file is not at; the second carries the same size with one byte of the content flipped, an identity nothing on disk can hold.

| instrument | fixture | expected | measured | verdict |
|---|---|---|---|---|
| resolving an input by content | must fire | found, off the recorded path, and the true address named | `present_off_the_recorded_path` | PASS |
| resolving an input by content | must stay silent | absent from the search area | `absent_from_the_search_area` | PASS |
| sorting a data file | must fire | `undeclared` | `undeclared` | PASS |
| sorting a data file | must stay silent | `declared_by_name` | `declared_by_name` | PASS |

Two paths under a data directory are put through bucket_of, the same sorter the census runs on every real file. One is named by nothing and sits in a directory named by nothing; the other carries a name some artifact declares.

The silent fixture was not answered by its size: 1 file(s) of exactly that size sit in the index and every one of them had to be hashed and rejected on content.
